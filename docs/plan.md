# Tick (滴答) — 产品需求文档

**Slogan:** 滴答一下，任务完成
**版本:** v1.0
**创建日期:** 2026-05-05

---

## 1. 产品概述

### 1.1 产品定位
一款极简、无负担的每日任务管理工具，帮助用户管理日常习惯和待办事项。

### 1.2 核心用户场景
用户打开App → 看到今天要做什么 → 做完一件点掉一件 → 查看完成统计

### 1.3 设计理念
**"减法设计"** —— 让用户少思考、少操作、多完成

---

## 2. 功能需求

### 2.1 任务属性定义

| 属性 | 说明 | 可选值/约束 |
|------|------|-------------|
| 内容 | 任务描述，一句话 | 必填，最大100字符 |
| 分类 | 任务归属分类 | 生活、工作、健康（固定三种） |
| 期限类型 | 任务的时间属性 | 日常、近期、长期 |
| 日常选项 | 当期限为"日常"时的重复模式 | 每天、每工作日（周一至周五） |
| 状态 | 任务的当前进度 | 待完成、已完成 |
| 创建时间 | 任务创建的时间戳 | 自动生成 |

#### 2.1.1 期限类型详细说明

| 期限类型 | 含义 | 显示规则 |
|----------|------|----------|
| 日常-每天 | 每天重复的任务 | 每日固定显示在列表顶部 |
| 日常-每工作日 | 周一至周五重复的任务 | 工作日显示在列表顶部；周末不显示、不生成每日记录 |
| 近期 | 需在近期完成的一次性任务（默认近7天窗口） | 显示在日常任务下方；超过7天未完成 → 自动归入长期区域，标注"超过7天" |
| 长期 | 长期规划任务，无明确时间限制 | 折叠显示，点击展开 |

#### 2.1.2 状态定义

| 状态 | 含义 | 视觉表现 |
|------|------|----------|
| 待完成 | 任务尚未完成 | 圆形圆圈，橙色/主题色 |
| 已完成 | 任务已完成 | 勾选标记，灰色文字+划线 |

### 2.2 核心功能清单

#### 2.2.1 首页（今日任务）— P0

| 功能 | 描述 |
|------|------|
| 今日任务列表 | 展示当日所有任务，分组显示 |
| 筛选 Tab | 顶部Tab切换：全部 / 日常 / 近期 |
| 日常任务置顶 | 日常任务固定显示在列表顶部（当筛选为"全部"时） |
| 任务分组展示 | 未完成在上，已完成在下 |
| 一键状态切换 | 点击任务圆圈直接切换状态（待完成↔已完成） |
| 快速编辑 | 长按任务弹出快速编辑菜单（编辑分类/编辑期限） |
| 滑动删除 | 左滑任务显示删除按钮，点击后弹出确认对话框 |
| 折叠/展开长期任务 | 长期任务默认折叠在底部；有已完成项时标题显示"长期规划 (N个已完成)" |
| 空状态引导 | 无任务时显示鼓励语 + 可点击示例任务 + "创建第一个任务"按钮 |
| 今日完成计数 | 日期栏下方显示"今日完成 3/5"，最小可行的反馈闭环 |

#### 2.2.2 添加任务 — P0

| 功能 | 描述 |
|------|------|
| FAB 入口 | 浮动按钮，点击进入添加页面 |
| 手动填写 | 内容输入 / 分类选择 / 期限选择 / 日常选项 / 提醒时间 |
| AI 智能解析 | 开关默认开启，自然语言输入自动解析并填充所有字段 |
| 解析结果预览 | AI 解析结果实时显示，用户可手动修改任意字段后保存 |
| 保存并返回 | 保存后返回首页并刷新列表 |

**AI 智能解析能力：**
- 提取任务内容
- 自动分类（生活 / 工作 / 健康）
- 自动判断期限类型（日常 / 近期 / 长期）
- 自动设置日常选项（每天 / 每工作日）
- 自动设置提醒时间

**解析示例：**

| 用户输入 | 解析结果 |
|----------|----------|
| "以后每天晚上 10 点提醒我喂小乌龟" | 内容:喂小乌龟, 分类:生活, 期限:日常-每天, 提醒:22:00 |
| "明天上午 9 点跟老板开会" | 分类:工作, 期限:近期, 提醒:09:00 |
| "每周一到周五早上 7 点起床" | 期限:日常-每工作日, 提醒:07:00 |
| "月底前完成项目报告" | 期限:近期 |
| "学习英语" | 期限:长期 |

#### 2.2.3 编辑任务 — P0

| 功能 | 触发方式 | 可编辑内容 |
|------|----------|------------|
| 快速编辑菜单 | 长按任务 | 分类 / 期限 / 日常选项 |
| 完整编辑页 | 点击任务文字区域 | 内容 / 分类 / 期限 / 日常选项 / 提醒时间 / 删除任务 |

#### 2.2.4 期限类型变更规则 — P0

| 变更方向 | 行为 |
|----------|------|
| 日常 → 近期 | 已生成的 daily_record 保留；即日起不再每日生成 |
| 日常 → 长期 | 已生成的 daily_record 保留；即日起不再每日生成；任务移入长期折叠区 |
| 近期 → 日常-每天 | 立即生成今天的待完成记录；之后每天生成 |
| 近期 → 日常-每工作日 | 立即生成今天的待完成记录（若今天是工作日）；之后每工作日生成 |
| 长期 → 日常 | 立即生成今天的待完成记录；之后按日常规则生成 |
| 长期 → 近期 | 任务移入近期区域 |

#### 2.2.5 每日任务生成规则 — P0

| 规则 | 描述 |
|------|------|
| 触发时机 | 用户打开 APP 时检查并生成 |
| 每天任务 | 今天无记录 → 生成今天的待完成记录 |
| 每工作日任务 | 今天无记录 + 今天是工作日 → 生成今天的待完成记录 |
| 不补中间记录 | 中间空缺不补生成，用户没机会完成就当没发生过 |

#### 2.2.6 任务生命周期

| 场景 | 规则 |
|------|------|
| 新建日常任务 | 生成一条当天的待完成记录 |
| 新建一次性任务（近期/长期） | 默认状态为"待完成" |
| 删除任务 | 仅标记为"已删除"，每日记录保留；已删除任务不在列表中显示，其记录仍参与统计 |
| 任务完成 | 点击切换为"已完成"，可再次点击撤销回"待完成" |
| 打开APP | 检查日常任务，生成今天的待完成记录（不补中间） |

#### 2.2.7 提醒功能 — P0

| 任务类型 | 提醒方式 | 提醒数据 |
|----------|----------|----------|
| 日常任务 | 每日固定时间提醒 | 仅存时间（HH:mm），每天固定时刻触发 |
| 近期任务 | 一次性提醒 | 存日期+时间（YYYY-MM-DD HH:mm），到期提醒一次 |
| 长期任务 | 不提供提醒 | — |

**提醒设置选项：** 不设置 / 预设时间（08:00, 09:00, 12:00, 18:00, 20:00, 21:00）/ 自定义时间

**数据区分：** 日常任务的提醒字段仅存 `HH:mm`，近期任务的提醒字段存 `YYYY-MM-DD HH:mm`（包含日期）。解析时根据期限类型自动区分。

**通知权限：** 首次使用时请求通知权限。权限被拒绝时，任务仍可正常使用，但不发送通知。

**通知行为细节：**

| 场景 | 行为 |
|------|------|
| App 在前台 | 通知以顶部横幅显示，不震动，3秒后自动消失 |
| App 在后台 | 系统通知中心显示，点击跳转到首页 |
| 点击通知 | 跳转到首页，高亮对应任务2秒 |
| 多个同时触发 | 3条以内逐条显示；超过3条合并为"你有 N 个待完成任务" |
| 权限请求时机 | 创建第一个带提醒的任务时请求（非App启动时），上下文更有说服力 |
| 权限被拒后 | 任务正常创建，不发送通知。在添加任务页提醒字段旁显示"通知已关闭，前往设置开启"小字链接 |

**通知内容格式：** 标题=[任务内容]，内容=来自"XXX"分类的任务提醒

### 2.3 AI 解析交互细节

| 场景 | 行为 |
|------|------|
| 解析触发方式 | 用户停止输入 600ms 后自动触发（debounce），非每次按键 |
| 解析中再次输入 | 取消当前解析，重置 debounce 计时器，用最新输入触发新解析 |
| 解析超时 | 30秒后自动降级为手动模式，提示"AI解析超时" |
| 用户手动取消 | 输入框右侧 X 按钮或关闭 AI 开关 |
| 解析结果修改 | 用户修改任一自动填充字段后，不重新解析其他字段（字段独立） |
| 不支持的语言 | 检测到非中文输入 → 不调用 API，提示"目前仅支持中文输入" |
| AI 开关关闭后 | 保留上次解析结果在表单中，用户可继续手动修改 |
| AI 开关重新打开 | 用当前输入框内容重新触发解析 |

### 2.4 跨午夜行为

| 场景 | 行为 |
|------|------|
| App 在前台跨过 00:00 | 自动触发日常任务生成 + 刷新列表，300ms 过渡动画 |
| App 在后台跨过午夜后打开 | 正常检查并生成今日记录（与普通打开行为一致） |
| 23:58 的任务完成记录 | 归属到当前日期（23:58 的那一刻），跨午夜不影响已完成记录 |

### 2.3 P1 — 重要功能

#### 2.3.1 统计页面

| 统计项 | 计算方式 |
|--------|----------|
| 昨日完成率 | 昨日完成数 / 昨日任务总数 |
| 本周完成率 | 近7天完成数 / 近7天任务总数 |
| 本月完成率 | 近30天完成数 / 近30天任务总数 |
| 分类完成统计 | 按分类（生活/工作/健康）聚合记录数据 |

#### 2.3.2 AI 统计分析与建议

- **每日总结：** 每天晚上 8 点自动生成，显示在统计页面顶部
- **每周报告：** 每周日晚上自动生成，包含更深入的分析
- **分析内容：** 完成情况总结、亮点和不足、各分类完成情况对比、个性化改进建议
- **风格要求：** 3-5句话，积极鼓励的语气，建议具体可执行（不说"提高效率"这种空话）
- **重新生成：** 提供"重新生成"按钮，用户可获取不同的分析结果

## 3. 数据模型（概念设计）

### 3.1 任务模板
存储用户创建的任务定义（相当于"任务类型"），包含：内容、分类、期限类型、日常选项、提醒时间、是否已删除、创建/更新时间。

### 3.2 每日任务记录
每天为日常任务生成的实例记录，包含：关联的任务模板、生成时的任务内容快照、分类、状态（待完成/已完成）、完成时间、记录日期、提醒时间。

### 3.3 AI 分析记录
存储 AI 生成的统计分析和建议，包含：分析类型（日总结/周报告）、分析周期起止日期、分析内容、生成时间。

### 3.4 核心设计约束

- **任务的删除是软删除**：标记"已删除"而非物理删除，每日记录保留
- **已删除任务不出现在任何列表**，但其历史记录仍参与统计
- **每日记录的生成是幂等的**：同一天同一任务不会生成多条记录
- **统计数据基于每日记录计算**，而非任务模板

## 4. 交互设计

### 4.1 状态切换逻辑

```
待完成 ──点击圆圈──→ 已完成
已完成 ──点击圆圈──→ 待完成（支持撤销）
```

### 4.2 页面跳转流程

```
首页(今日任务列表)
    ├── 点击Tab ──→ 筛选切换（全部 / 日常 / 近期）
    ├── 点击日期栏右侧统计图标 ──→ 统计页面
    ├── 点击FAB ──→ 添加任务页面 ──→ 保存 ──→ 返回首页
    ├── 点击任务状态圆圈 ──→ 状态切换（待完成 ↔ 已完成）
    ├── 左滑任务 ──→ 显示删除按钮 ──→ 确认删除 ──→ 删除
    ├── 长按任务 ──→ 弹出快速编辑菜单（编辑分类 / 编辑期限 / 取消）
    └── 点击任务文字区域 ──→ 编辑任务页面（完整编辑 + 删除按钮）
```

### 4.3 快速编辑菜单与完整编辑页的区分

**快速编辑菜单**（长按触发，轻量修改）：
- 编辑分类：切换生活/工作/健康
- 编辑期限：切换日常/近期/长期，日常任务可切换每天/每工作日
- 取消：关闭菜单，不做任何修改

**完整编辑页**（点击任务文字区域进入）：
- 编辑内容：修改任务描述文字
- 编辑分类 / 编辑期限 / 编辑提醒时间
- 删除任务：软删除

**设计意图**：分类和期限是最常调整的属性，长按即可快速切换；修改文字内容、删除等操作在完整编辑页中进行。

### 4.4 筛选Tab规则

| Tab | 显示内容 |
|-----|----------|
| 全部 | 日常任务置顶 → 近期任务居中 → 长期任务折叠在底部；各组内未完成在上、已完成在下 |
| 日常 | 仅显示日常任务（每天+每工作日）；未完成在上、已完成在下 |
| 近期 | 仅显示近期任务；未完成在上、已完成在下 |

> 长期任务仅出现在"全部"Tab 底部折叠区域，不出现于"日常"和"近期"Tab。有意设计，避免长期任务稀释日常任务的聚焦感。

### 4.5 首页列表布局

```
┌─────────────────────────────────┐
│  [全部]  [日常]  [近期]  [📊]    │  ← 筛选Tab + 统计入口（默认"全部"）
├─────────────────────────────────┤
│  📅 2026年4月24日 星期五         │  ← 顶部日期栏
├─────────────────────────────────┤
│  📌 日常任务                     │  ← 分组标题
├─────────────────────────────────┤
│  ○ 喂小乌龟          [生活]     │  ← 待完成（橙色圆圈）
│  ● 帮娃完成游戏日常  [生活]     │  ← 已完成（灰色+划线）
├─────────────────────────────────┤
│  📋 近期任务                 │  ← 分组标题
├─────────────────────────────────┤
│  ○ 超市买菜          [生活]     │  ← 近期任务
├─────────────────────────────────┤
│  📦 长期规划          [▶]       │  ← 长期任务折叠（点击展开）
└─────────────────────────────────┘
                        [+]       │  ← FAB添加按钮
```

**视觉规则：**
- ○ = 待完成，橙色/主题色
- ● = 已完成，灰色文字 + 删除线
- ▶ = 长期任务折叠，点击展开

### 4.6 触摸交互参数

移动端核心触摸交互需明确参数，避免 iOS/Android 行为不一致。

| 参数 | 值 | 说明 |
|------|-----|------|
| 圆圈触摸区域 | 最小 44pt | 遵循 iOS HIG / Android Material，视觉圆圈可小于触摸区域 |
| 长按触发时长 | 500ms | 触发快速编辑菜单，期间给触觉反馈（Haptic） |
| 左滑删除阈值 | 滑动超过 80pt 或速度 > 200pt/s | 满足任一条件触发；释放后弹性吸附回原位或贴边显示删除按钮 |
| FAB 底部安全区 | `safeAreaBottom + 16pt` | 有 Home Indicator 的设备上悬浮在安全区上方 |
| FAB 滚动行为 | 向下滚动时隐藏，向上滚动时显示 | 标准 Material Design 行为 |

### 4.7 动效设计

"减法设计"中动效是品质信号。没有动效的极简 = 简陋。

| 交互 | 动效 | 时长 |
|------|------|------|
| 点击完成圆圈 | 圆圈缩小 → 勾选弹入 → 橙色变灰色 | ~300ms |
| 撤销完成 | 勾选消失 → 圆圈弹回 → 灰色变橙色 | ~300ms |
| 删除任务 | 任务项左滑出 + 淡出消失 | ~250ms |
| 完成项排序 | 从"未完成"滑入"已完成"分组 | ~300ms |
| 长期任务展开/折叠 | 高度动画，平滑展开折叠区域 | ~200ms |
| Tab 切换 | 列表淡入淡出 | ~200ms |
| FAB 点击 | 按钮缩放反馈 | ~100ms |

**设计原则：** 动效用于传达因果关系（操作 → 结果）、保持空间连续感（项目不会突然消失/出现）。不做装饰性动效。

## 5. 交互状态覆盖

每个页面的每种状态必须被设计覆盖。✅ = 已定义，❌ = 需补全。

| 页面/功能 | 加载中 | 空状态 | 正常 | 错误 | 部分数据 |
|-----------|--------|--------|------|------|----------|
| 今日任务列表 | 上次缓存数据 + 顶部轻量刷新指示器 | 鼓励语 + 可点击示例任务 + 创建按钮 | 任务分组列表 + 今日完成计数 | 数据库错误 → "数据加载失败，请重启App" | 部分分组加载失败 → 显示已加载部分，失败分组提示"加载失败" |
| 全部任务已完成 | — | — | 所有任务在已完成分组，页面顶部显示"今日全部完成 🎉" | — | — |
| AI 任务解析 | 输入框下方 "✨ 正在解析..." + spinner，超时30秒后自动降级 | — | 解析结果预览，用户可逐字段修改 | 降级提示 + 手动模式可用，附具体原因 | 已识别字段预填，未识别留空 |
| 手动添加任务 | — | — | 表单可填写 | "保存失败，请重试" | 内容超100字符 → 内联提示截断，其他字段正常 |
| 编辑任务页 | 加载任务数据 → 显示已填表单 | 任务不存在 → "任务已被删除" + 返回首页 | 完整表单可编辑 | "保存失败，请重试" | — |
| 统计页面 | 数字加载 + AI分析spinner | "今天刚开始，完成第一个任务吧！" | 完成率 + 分类聚合 + AI分析 | AI分析失败 → 仅显示数字 + "生成分析"按钮 | 部分分类加载失败 → 显示已成功部分 |
| 通知 | — | — | 按时触发 | 权限被拒 → 静默，任务照常 | 多个同时触发 → 3条以内逐条显示，超过3条 → 汇总"你有N个待完成任务" |

**设计原则：** 任何状态用户都能理解发生了什么、知道下一步该做什么。不做空白页、不做死胡同。

**视觉规范：** 详见 `docs/VISUAL.md`（色板、字体层级、间距尺度、组件规格、暗色模式、可访问性）。

### 5.1 暗色模式与字体缩放

- **暗色模式：** 所有页面支持，跟随系统设置自动切换
- **字体缩放：** 支持系统 Dynamic Type / 字体缩放到 135%
- **触觉反馈：** 任务完成时提供轻量振动（UIKit `UIImpactFeedbackGenerator`），增强满足感
