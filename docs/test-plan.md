## 测试策略

### 三层测试架构

| 层级 | 工具 | 占比 | 说明 |
|------|------|------|------|
| 单元测试 | Jest | 60% | 纯逻辑：数据模型、状态管理、工具函数 |
| 自动化 QA | gstack `/qa`、`/browse` | 30% | 浏览器自动化：UI交互、页面流程、状态验证 |
| 手工验证 | gstack `/qa-only` | 10% | 报告模式：发现问题不修，生成bug报告 |

### 核心策略说明

项目使用 expo-web 在浏览器中运行 Web 版本，使得 gstack 浏览器工具（`/browse`、`/qa`、`/qa-only`、`/canary`）可以直接进行自动化测试。gstack QA 替代传统 E2E 框架（Detox/Cypress），零额外依赖。

### 开发工作流

```
编写代码 → npm test (单元) → 启动 Web → gstack /qa (自动化) → 修bug → 循环
```

## 1. 单元测试 (Jest)

### 1.1 数据模型逻辑

- 任务模板 CRUD（创建/读取/更新/软删除）
- 每日记录生成逻辑（每天/每工作日/幂等检查）
- 任务状态切换（待完成↔已完成）
- 筛选逻辑（全部/日常/今日其他）
- 排序逻辑（日常置顶/未完成在上/长期折叠）

### 1.2 AI 解析函数

- 正常输入解析（自然语言 → 结构化字段）
- 边界输入（空字符串、超长、纯符号、纯英文）
- 解析降级（部分字段识别/全部未识别）

### 1.3 统计计算

- 昨日/本周/本月完成率计算
- 分类完成统计聚合
- 空数据/边界值处理

### 1.4 状态管理

- Store action 正确性
- 乐观更新与回滚
- 并发操作安全

## 2. gstack QA 自动化测试

### 2.1 使用方式

```bash
# 启动开发服务器
npm run web

# 自动化 QA（测试+修bug）
/qa http://localhost:8081

# 仅报告不修
/qa-only http://localhost:8081

# 部署后监控
/canary http://localhost:8081
```

### 2.2 核心测试场景

#### 场景 1: 首次使用 → 空状态
```
1. 打开首页（清空数据）
2. 验证：空状态引导文案显示
3. 验证：示例任务列表可见
4. 验证："创建第一个任务"按钮存在
5. gstack browse: 截图验证
```

#### 场景 2: 手动创建任务
```
1. 点击 FAB → 进入添加页
2. 输入任务内容 "超市买菜"
3. 选择分类 "生活"
4. 选择期限 "近期"
5. 点击保存
6. 验证：返回首页，任务显示在"今日其他"分组
7. 验证：任务圆圈为橙色○（待完成状态）
```

#### 场景 3: AI 智能创建任务
```
1. 点击 FAB → 进入添加页
2. 确认 AI 开关默认开启
3. 输入 "每天晚上10点喂小乌龟"
4. 验证：下方显示解析预览（内容/分类/期限/提醒）
5. 验证：分类=生活, 期限=日常, 提醒=22:00
6. 点击保存
7. 验证：返回首页，任务出现在"日常任务"分组
```

#### 场景 4: 状态切换
```
1. 点击任务圆圈
2. 验证：圆圈变为勾选●，文字变灰+划线
3. 再次点击
4. 验证：恢复为圆圈○，文字恢复
```

#### 场景 5: 左滑删除
```
1. 左滑任务项
2. 验证：显示红色删除按钮
3. 点击删除按钮
4. 验证：弹出确认对话框
5. 点击确认
6. 验证：任务从列表消失
```

#### 场景 6: 长按快速编辑
```
1. 长按任务项
2. 验证：弹出快速编辑菜单
3. 选择"编辑分类" → 选择"工作"
4. 验证：任务分类标签变为[工作]
```

#### 场景 7: Tab 筛选切换
```
1. 点击"日常" Tab
2. 验证：仅显示日常任务
3. 点击"今日其他" Tab
4. 验证：仅显示近期任务
5. 点击"全部" Tab
6. 验证：日常置顶+近期居中+长期折叠底部
```

#### 场景 8: 统计页面
```
1. 完成/撤销几个任务
2. 切换到统计页面
3. 验证：完成率数字正确
4. 验证：分类统计聚合正确
5. 验证：AI 分析卡片显示（若 API 可用）
```

#### 场景 9: 每日任务生成
```
1. 创建日常-每天任务
2. 关闭再打开 APP
3. 验证：今日记录已生成，状态为待完成
4. 再次打开 APP
5. 验证：不重复生成（幂等）
```

#### 场景 10: 工作日逻辑
```
1. 创建一个日常-每工作日任务
2. 若今天是周六/周日：验证该任务不出现
3. 若今天是工作日：验证该任务出现在列表
```

### 2.3 边界场景

| 场景 | 验证点 |
|------|--------|
| 快速双击状态圆圈 | 不产生重复状态切换 |
| 输入超长任务内容 (>100字符) | 输入截断或提示 |
| AI 解析时网络断开 | 降级为手动输入模式 |
| 大量任务 (50+条) | 列表可滚动，性能正常 |
| 全部任务已完成 | 已完成分组显示所有任务 |
| 零任务时打开统计 | 完成率显示"暂无数据" |

## 3. gstack QA 的分级使用

### Quick QA（快速检查）
```bash
/qa http://localhost:8081 --tier quick
```
仅测试 P0 关键路径：创建任务、状态切换、删除、筛选 Tab

### Standard QA（标准检查）
```bash
/qa http://localhost:8081
```
全部 P0 + P1 功能，包含 AI 解析和统计

### Exhaustive QA（全面检查）
```bash
/qa http://localhost:8081 --tier exhaustive
```
包含所有边界场景、性能验证、响应式测试
